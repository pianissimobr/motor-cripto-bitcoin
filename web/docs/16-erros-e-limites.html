Erros e limites

Erro de pedido volta um JSON com código. Erro de upstream diz que LNbits ou Esplora falharam. Limite estourado é recusa, não truncamento silencioso.

ObjetivoDecidir, pelo code, se a loja corrige o corpo, espera, ou troca o external_id.

Forma

{
  "error": {
    "code": "validation_error",
    "message": "corpo invalido",
    "details": []
  }
}

Mensagem de erro 500 não sai para o cliente. O código público é internal_error.

HTTPcodeO que a loja faz
400validation_errorCorrige o campo. O corpo não foi aceito.
401unauthorizedChave, relógio, nonce ou assinatura. Não repita o mesmo nonce.
404not_foundId de outra loja, ou cobrança que não existe.
409conflictMesmo external_id com outro valor, id em criando ou falha_criacao, ou cancelamento fora de pendente. Em criando, tente de novo.
413bad_requestCorpo acima de 64 KiB.
429limite do FastifyO teto é por cliente da API (o cabeçalho Authorization), 120 pedidos por minuto. No webhook do LNbits o teto é por IP. Espere a janela.
502upstream_errorLNbits não criou a invoice. Use outro external_id. O anterior ficou falha_criacao.
503service_unavailable/ready recusou. A operação olha o check que falhou.

Limites do corpo

CampoLimite
external_id1 a 128 caracteres, sem espaço nas pontas
descriptionaté 200 caracteres
amount_satsinteiro positivo até 21.000.000 BTC
expires_in_seconds30 a 86.400
X-Nonce8 a 128 caracteres
índice HDaté BTC_MAX_INDEX, padrão 100.000. Cada cobrança, mesmo a que falha, consome um índice
Como conferirMande amount_sats: "10.5". A resposta é 400. Mande o mesmo external_id com outro inteiro. A resposta é 409. Os dois não criam endereço novo no segundo caso; o 409 de valor diferente acontece porque a cobrança já existe.
