Parte 4 · Operar e falhar

Operação

A API e o worker são dois processos. A API cria cobrança. O worker é quem percebe o pagamento, avisa a loja e varre.

ObjetivoSaber qual job olhar quando um pedido não anda, e qual URL chama para ver o conjunto.

Subir

O serviço mora em services/btc-payments. O desenvolvimento sobe o Postgres com Docker Compose, aplica as migrations e roda npm run dev num terminal e npm run worker em outro. A carteira de sweep nasce com npm run wallet:init: o mnemonic aparece uma vez, o BTC_XPUB vai para o ambiente, o xprv fica só no keystore.

Em produção, o Compose com Caddy publica o domínio. O worker monta ./data só para ler o keystore, em modo somente leitura. O passo a passo de deploy, backup e restore está em services/btc-payments/docs/runbook.md.

Os jobs

JobPadrãoFunção
lightning-reconcile15 sRelê invoices pendentes no LNbits quando o webhook de entrada se perde.
expiry10 sMarca expirado ou parcial, ou espera confirmação se o valor já está no endereço.
onchain-watch15 sLê UTXOs, confirmações e reorg no Esplora.
webhook-delivery10 sEntrega a outbox e apaga nonces vencidos.
sweep30 sMonta, transmite e acompanha a varredura, inclusive RBF.

Cada job espera o próprio ciclo anterior terminar. Jobs diferentes rodam ao mesmo tempo. Um lote padrão tem 50 registros.

O que o admin lê

GET /admin/api/status junta contagens de intents, webhooks e sweeps, a saúde do LNbits e do Esplora, a rede, o fingerprint do xpub, o modo do signer e a soma de paid_amount_sats por cliente e por trilho. Essa soma mostra quanto de cada loja está misturado na carteira fria e no LNbits; a custódia continua única.

GET /health só diz que o processo responde. GET /ready falha com 503 se o banco, o xpub, a carteira fria, o LNbits ou o Esplora não passam. É essa a URL que um balanceador deve usar.

Se ALERT_WEBHOOK_URL existir, o worker avisa job que quebrou, sweep manual ou falho, pagamento duplicado e reorg.

Como conferircurl http://localhost:4580/ready devolve ok: true e um objeto checks. Qualquer ok: false dentro de checks é o componente que impede pagamento novo de ser observado.
