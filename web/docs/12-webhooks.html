Webhooks

O motor grava o evento antes de tentar entregar. A loja só acredita no POST se a assinatura fechar com o corpo cru que chegou.

ObjetivoVerificar X-Webhook-Signature e tratar o mesmo event_id duas vezes sem duplicar o pedido.

Eventos

  • payment_intent.paid
  • payment_intent.paid_late
  • payment_intent.partial
  • payment_intent.expired
  • payment_intent.canceled
  • payment_intent.reorged

Headers e corpo

X-Webhook-Signature: t=1792700000,v1=<hex>
X-Webhook-Event: payment_intent.paid
X-Webhook-Delivery: <uuid da entrega>
Content-Type: application/json
{
  "event": "payment_intent.paid",
  "event_id": "uuid",
  "created_at": "2026-10-29T12:04:30.000Z",
  "data": {
    "id": "uuid",
    "external_id": "pedido-123",
    "status": "pago",
    "amount_sats": "10000",
    "paid_amount_sats": "10000",
    "paid_rail": "lightning",
    "paid_at": "2026-10-29T12:04:30.000Z",
    "overpaid_sats": "0"
  }
}

A assinatura é HMAC-SHA256(webhookSecret, timestamp + "." + rawBody). O timestamp é o valor de t. Use o corpo exatamente como chegou, antes de fazer parse.

import { createHmac, timingSafeEqual } from 'node:crypto';

const header = request.headers['x-webhook-signature'];
const parts = Object.fromEntries(header.split(',').map((p) => p.split('=')));
const expected = createHmac('sha256', webhookSecret)
  .update(`${parts.t}.${rawBody}`)
  .digest('hex');
const ok = expected.length === parts.v1.length
  && timingSafeEqual(Buffer.from(expected), Buffer.from(parts.v1));

Entrega

Resposta 2xx marca o evento como entregue. Qualquer outra coisa, ou timeout, entra na fila de novo: 60 segundos, 5 minutos, 30 minutos, 2 horas, 6 horas e 24 horas. O padrão para de tentar na sexta falha (WEBHOOK_MAX_ATTEMPTS). O operador pode reenfileirar com POST /admin/api/webhooks/:id/replay.

Guarde event_id ou X-Webhook-Delivery. O mesmo evento pode chegar mais de uma vez se a loja respondeu devagar e o motor não viu o 2xx.

CuidadoA chave interna que evita dois webhooks iguais é intent:{id}:{tipo}:{version}. A mesma transição não duplica. pago → reorg → pago gera um segundo payment_intent.paid, porque a version da cobrança mudou. A entrega não segue redirect.
