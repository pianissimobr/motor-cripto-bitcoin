Preparar a loja

Antes da primeira cobrança, o operador cria o cliente da API. A resposta com os três segredos aparece uma vez. O banco guarda o hash da chave e o restante cifrado.

ObjetivoCriar o cliente, guardar os segredos e apontar o webhook para um endpoint HTTPS da loja.

Criar

POST /admin/api/clients com Authorization: Bearer e o ADMIN_TOKEN.

{
  "name": "Minha loja",
  "webhook_url": "https://loja.example/webhooks/btc"
}

Resposta 201, em camelCase:

{
  "id": "uuid",
  "name": "Minha loja",
  "webhookUrl": "https://loja.example/webhooks/btc",
  "apiKey": "mk_btc_live_...",
  "requestSecret": "...",
  "webhookSecret": "...",
  "createdAt": "2026-10-29T12:00:00.000Z"
}

apiKey autentica. requestSecret assina os pedidos. webhookSecret verifica o que o motor enviar depois. Anote os três fora do repositório. A listagem GET /admin/api/clients devolve nome, prefixo da chave, URL e status. Não devolve segredo.

O que a loja precisa ter pronto

  • Um endpoint que aceite POST com JSON e responda 2xx depressa, depois de gravar o evento.
  • HTTPS em produção. O motor recusa http ao criar o cliente quando NODE_ENV=production.
  • A verificação do header X-Webhook-Signature, no capítulo de webhooks.

Não há cadastro de carteira por loja. A loja não envia endereço de destino. A carteira fria é uma configuração do processo, feita antes de subir o worker.

CuidadoPerder requestSecret impede a loja de assinar. O motor não tem rota de rotação neste serviço. Criar outro cliente é o caminho se o segredo vazou; as cobranças antigas continuam no cliente antigo.
