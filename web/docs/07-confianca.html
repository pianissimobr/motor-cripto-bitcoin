Confiança

Cada chamada da loja prova duas coisas: quem é, e que aquele corpo exato foi enviado agora. A API key sozinha não basta.

ObjetivoMontar a string canônica e a assinatura HMAC sem o motor reescrever o JSON.

Os headers

Authorization: Bearer mk_btc_live_...
X-Timestamp: 1792700000
X-Nonce: um-valor-unico-com-8-a-128-chars
X-Signature: v1=<hex>
Content-Type: application/json

A chave é comparada pelo hash SHA-256. O segredo de pedido fica cifrado no banco e só sai da memória para calcular o HMAC. A assinatura usa esse segredo, não a API key.

A string canônica

METHOD
PATH
TIMESTAMP
NONCE
SHA256(rawBody)

Cinco linhas, separadas por \n. METHOD em maiúsculas. PATH sem query string: /v1/payment-intents, nunca /v1/payment-intents?external_id=…. O hash é do corpo cru, os bytes enviados, não de um JSON reformatado. GET sem corpo assina a string vazia.

A assinatura é HMAC-SHA256 dessa string, em hex. O header aceita o hex puro ou com o prefixo v1=.

O que é recusado

  • Timestamp que não seja só dígitos, ou que esteja a mais de 300 segundos do relógio do servidor.
  • Nonce com menos de 8 ou mais de 128 caracteres.
  • Nonce já usado por aquele cliente. O registro dura 10 minutos, mais do que a janela do timestamp, então um pedido capturado não pode ser repetido.
  • Assinatura diferente, comparada em tempo constante.

Exemplo

import { createHash, createHmac, randomUUID } from 'node:crypto';

const body = JSON.stringify({ external_id: 'pedido-123', amount_sats: '10000' });
const timestamp = Math.floor(Date.now() / 1000).toString();
const nonce = randomUUID();
const canonical = [
  'POST',
  '/v1/payment-intents',
  timestamp,
  nonce,
  createHash('sha256').update(body).digest('hex'),
].join('\n');
const signature = createHmac('sha256', requestSecret).update(canonical).digest('hex');

Envie body como corpo da requisição, o mesmo buffer que entrou no hash. Se a biblioteca JSON mudar a ordem das chaves depois, a assinatura não fecha.

Como conferirUma segunda chamada com o mesmo nonce, ainda dentro da janela, responde 401 com nonce reutilizado. Um corpo com um espaço a mais, assinado sem esse espaço, responde assinatura invalida.
