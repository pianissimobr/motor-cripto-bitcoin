Parte 3 · O contrato

Confiança

O admin apresenta um token. A loja assina cada pedido. As duas provas não se misturam, e a segunda exige que o JSON seja exatamente o que foi enviado.

ObjetivoMontar um pedido /v1 que a API aceite, e reconhecer por que um corpo “igual” ainda falha.

O problema

Uma API key sozinha, se vazar num log, permite criar cobranças para sempre. A assinatura obriga quem chama a provar que também tem o request_secret, naquele segundo, para aquele corpo. Um nonce impede que o mesmo pedido assinado seja repetido por um terceiro.

O método

Admin

Toda rota /admin/api/* leva:

Authorization: Bearer <ADMIN_TOKEN>

Não há assinatura de corpo. Token ausente responde 401. Token errado responde 403. Vinte falhas no mesmo IP, dentro de um minuto, passam a responder 429 mesmo que a vigésima primeira tentativa traga o token certo. A janela é de um minuto.

Cliente da API

Toda rota /v1/* leva a chave e três headers:

Authorization: Bearer mk_live_...
X-Timestamp: 1792700000
X-Nonce: pedido-150-01
X-Signature: v1=<hex>

A string assinada, com quebras de linha reais entre as cinco linhas, é:

METHOD
PATH
TIMESTAMP
NONCE
SHA256(RAW_BODY)

METHOD vai em maiúsculas. PATH não inclui a query: GET /v1/links?limit=10 assina /v1/links. O hash é SHA-256 do corpo cru, em hex minúsculo. GET e POST sem corpo assinam o hash da string vazia. O HMAC é SHA-256 com o request_secret, e o header recebe o prefixo v1=.

O timestamp é Unix em segundos, aceito numa janela de 300 segundos. O nonce tem de 8 a 128 caracteres e só pode ser usado uma vez por cliente. Reuso responde 409.

CuidadoAssine os bytes que vão no fio. Se você monta um objeto, assina, e depois o cliente HTTP reordena as chaves ou muda espaços, a assinatura deixa de bater. O caminho seguro é serializar uma vez, assinar essa string e enviar essa mesma string.

Idempotência

A chave é o header Idempotency-Key. Se ele não vier, o motor usa external_id. A mesma chave com o mesmo payload devolve o link original e reused: true. A mesma chave com outro payload responde 409. O payload comparado inclui external_id, amount_cents, ramp_profile_id, wallet_id e final_url. external_id também é único por cliente.

O contrato

POST /v1/links
Idempotency-Key: pedido-150

{"external_id":"pedido-150","amount_cents":15000,"ramp_profile_id":"...","wallet_id":"..."}

O hex do SHA-256 dessa string exata entra na quinta linha. Não use um JSON “bonito” se a assinatura foi feita no JSON compacto, nem o contrário.

O que recusamos

HTTPQuando
401Chave ausente ou desconhecida, header HMAC faltando, assinatura errada, timestamp fora da janela.
403Bearer de admin diferente do ADMIN_TOKEN.
409Nonce já usado, ou idempotência com outro corpo (idempotencia_conflitante).
429Vinte falhas de credencial naquele IP no último minuto, ou o teto global de 120 pedidos.

Como conferir

Como conferirRepita o mesmo POST /v1/links com o mesmo nonce. A segunda resposta é 409, “nonce ja utilizado”. Troque o nonce, mantenha a Idempotency-Key e o corpo. A resposta é 200 com reused: true e o mesmo id.
