Pagamentos Bitcoin

A loja pede uma cobrança em satoshis. O serviço devolve um QR com Lightning e um endereço. O worker avisa quando o pagamento se prova.

Estas páginas descrevem só services/btc-payments, na porta 4580. O menu à esquerda é a ordem de leitura.

Onde o sats para

Quem pagouOnde o valor fica
LightningNa wallet do LNbits ligada a LNBITS_API_KEY. Não segue para a carteira fria.
On-chainNo endereço daquela cobrança, até o worker enviar para COLD_WALLET_ADDRESS.

Os dois podem acontecer no mesmo pedido. Aí paid_rail fica both: o Lightning continua no LNbits e o on-chain vai para a carteira fria.

1. Para onde vai o dinheiroCarteira fria, LNbits, e o que a loja recebe de aviso. 2. O que você configuraOs dados que o repositório não inventa: token, xpub, LNbits, Esplora, endereço frio. 3. Criar a cobrançaO JSON do pedido e o que volta no QR. 4. Provar o pagamentoO que conta como pago em cada trilho, e o que é reorg. ContratoTodas as rotas, com os corpos.

O exemplo do livro é 10000 sats, escritos na URI como 0.00010000 BTC. A invoice dura 10 minutos. O endereço on-chain continua observado por 24 horas. Uma confirmação basta; a partir de 1.000.000 sats, três.
