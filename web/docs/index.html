O livro da API

Este livro ensina o que o motor de pagamentos Bitcoin faz, em que ordem ele faz, e qual chamada HTTP corresponde a cada passo. Ele é para a pessoa que integra a loja e para quem opera o admin.

ObjetivoSaber qual parte abrir conforme a pergunta: o que o motor é, como um pagamento anda, qual JSON enviar, ou o que fazer quando algo falha.

O motor não é a loja e não é uma carteira de celular. A loja pede uma cobrança com um valor em satoshis e um identificador de pedido. O motor devolve uma invoice Lightning e um endereço Bitcoin exclusivo, no mesmo QR. Quando o pagamento cai, o motor avisa a loja. O valor on-chain é varrido para a carteira fria do operador.

Este livro descreve o serviço em services/btc-payments, na porta local 4580. Ele não descreve Ramp, stablecoin nem a rede Polygon. Esse motor anterior ainda está na pasta src/ e não é o contrato desta API.

Leia na ordem se esta é a primeira vez. Se você já sabe o que quer chamar, a referência de rotas aponta o capítulo certo. O mapa do código continua em docs/guia.md.

Os números que voltam em todo o livro são estes: o pedido de exemplo vale 10000 satoshis, escritos na URI como 0.00010000 BTC. A invoice Lightning dura 10 minutos. O endereço on-chain continua observado por 24 horas depois disso. Uma confirmação basta no valor comum; a partir de 1.000.000 sats o padrão sobe para 3. Datas saem em UTC.
