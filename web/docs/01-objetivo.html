Parte 1 · O objetivo

O objetivo

A loja quer stablecoin numa carteira que ela escolheu. Quem paga usa reais. O motor existe para perceber o que a blockchain registrou e mover esse valor.

ObjetivoExplicar, sem abrir o código, o que o motor faz e o que ele se recusa a fazer.

O problema

Imagine uma cobrança de R$ 150,00. A pessoa paga na Ramp, em reais. A Ramp compra USDC e envia para um endereço. Sem um aviso da Ramp, a loja só fica sabendo se alguém olhar a rede. O motor é essa leitura automática.

O destino final não é um endereço global do servidor. Cada cliente da API cadastra as próprias carteiras. Uma cobrança só pode varrer para uma carteira que já esteja nessa lista, na mesma rede do perfil.

O método

  1. O operador cria o cliente da API e anota, uma única vez, a chave, o segredo de pedido e o segredo de webhook.
  2. O operador cadastra a carteira de destino. O sistema da loja não inventa esse endereço na hora da cobrança.
  3. O sistema da loja pede um link. O motor reserva um índice, deriva um endereço exclusivo e devolve a página pública.
  4. Quem paga abre a página, vê o valor e segue para a Ramp. O motor não participa desse pagamento.
  5. O worker lê transferências do contrato certo para aquele endereço, espera confirmações e avisa a loja.
  6. Uma carteira separada, só de gas, paga a taxa da rede. O USDC vai para a carteira allowlisted. O POL que sobra volta para a carteira de gas.

O contrato

O objetivo vira três superfícies HTTP, todas no mesmo processo, na porta local 4578 ou na PUBLIC_BASE_URL:

  • /admin/api/* para quem opera, com o ADMIN_TOKEN.
  • /v1/* para o sistema da loja, com API key e assinatura de cada pedido.
  • /p/:token e /health para quem não tem segredo de loja.

O valor em reais viaja como inteiro de centavos. O valor do token viaja como string de unidades mínimas. A URL da Ramp não aparece no JSON da API. Ela só existe dentro da página pública.

O que recusamos

  • Processar cartão, Pix ou dados da Ramp.
  • Aceitar um endereço de depósito enviado pela loja.
  • Varrer para uma carteira que não esteja allowlisted naquele cliente e naquela rede.
  • Tratar um e-mail ou um print da Ramp como pagamento.
  • Confirmar o pagamento antes das confirmações e do recibo da transação.

Como conferir

Como conferirAbra /health. A resposta é {"ok": true, "ts": "..."} com data em UTC, sem token. Se isso responde, a API está no ar. O pagamento em si só existe depois do worker.
