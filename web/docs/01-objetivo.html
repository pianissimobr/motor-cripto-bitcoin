Para onde vai o dinheiro

Lightning fica no LNbits. On-chain termina em COLD_WALLET_ADDRESS. A loja só fica sabendo pelo webhook.

LightningOn-chain
Quem recebe na horaA wallet do LNbits de LNBITS_API_KEYO endereço exclusivo daquela cobrança
Para onde segueFica nessa wallet. O serviço não saca.O worker envia para COLD_WALLET_ADDRESS
Quem guarda a chaveO LNbits que você conectouVocê, fora deste processo. O serviço só sabe o endereço

A carteira fria é uma só para todas as lojas. A wallet Lightning também. O serviço separa os pedidos por cliente da API e mostra a soma em GET /admin/api/status. Essa soma não é uma segunda carteira.

O caminho de um pedido

  1. Você cria o cliente da API e guarda a chave, o segredo do pedido e o segredo do webhook.
  2. A loja chama POST /v1/payment-intents com external_id e amount_sats.
  3. O serviço reserva o próximo endereço e pede uma invoice ao LNbits. A resposta traz os dois, mais o QR.
  4. A loja mostra o QR. Não há página de pagamento neste serviço.
  5. O worker relê o LNbits e o Esplora. Quando a prova cobre o pedido, avisa a loja.
  6. Se o pagamento foi on-chain, o worker varre esse endereço para a carteira fria. Se foi Lightning, o saldo permanece no LNbits.

Quem chama o quê

  • /v1/* é a loja, com API key e HMAC.
  • /admin/api/* é você, com Authorization: Bearer e o ADMIN_TOKEN.
  • POST /webhooks/lnbits é o LNbits. O corpo não prova o pagamento; o worker consulta o LNbits de novo.
  • /health e /ready não pedem segredo.
Como conferirGET /health responde ok: true e o nome btc-payments. GET /ready só passa se o Postgres, o xpub, a carteira fria, o LNbits e o Esplora respondem.
